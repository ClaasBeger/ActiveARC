P-ARC “non-grid output”: empty-list sentinels

Two P-ARC verifiers (verify_t30, verify_t33) return [] when the input cannot be parsed into the task’s expected structure. ActiveARC’s wrapper treats any non-rectangular int grid as an error and surfaces P-ARC verifier verify_tN returned non-grid output to the model. These are invalid-input sentinels, not crashes — the same verifiers succeed on hot-start / train grids.

test2_t30 — missing progression frames

  • Task Fill blank frames in a vertical strip of equal-size frames separated by full rows of color 6 (pink).
  • Outcome never solved (model_stop after many wrong tests); 1 non-grid query error on turn 0.
  • Raw verifier return on failing query [] (empty list).
  • ActiveARC wrap ValueError: P-ARC verifier verify_t30 returned non-grid output

Hot-start input (valid)

27×6

Separators are color 6; 4 equal frames of height 6.

Hot-start output

27×6

Failing query (turn 0)

36×4

Separators are color 5 (gray), not 6. Even as color-5 seps, frame heights would be [4, 5, 7, 8, 8] — unequal.

def verify_t30(grid):
    split = _split_frames(grid)   # looks for full rows of SEP=6
    if split is None:
        return []                 # ← sentinel: cannot parse as frame strip
    ...

Why []: the model used gray (5) bars between frames, but this verifier hard-codes separator color 6. _split_frames found no sep rows → returned None → verify_t30 returned []. Additionally the implied frame heights were unequal, which would also fail the equal-height check.

test2_t33 — odd one out rectangle

  • Task Among ≥3 colored objects, identify the unique odd-one-out by shape and return it as a cropped grid.
  • Outcome eventually correct after several wrong tests (query_count=30).
  • Raw verifier return on failing query [].
  • ActiveARC wrap ValueError: P-ARC verifier verify_t33 returned non-grid output

Hot-start input (valid)

15×12

5 objects; odd candidate index [2].

Hot-start output (odd shape)

2×3

Failing query (turn 0)

4×5

Only 2 objects (colors [1, 2]). Needs ≥3.

def verify_t33(grid):
    objs = _extract_objects(grid)
    if len(objs) < 3:
        return []                 # ← sentinel: too few objects
    cands = _odd_candidates(objs)
    if len(cands) != 1:
        return []                 # ← sentinel: no unique odd-one-out
    ...

Why []: the probe is a tiny 4×5 grid with only two colored blobs. The verifier requires at least three objects and exactly one odd-one-out candidate. This is a clear out-of-domain exploration query, not a broken verifier — hot-start and later successful path work fine.

How ActiveARC wraps it

# framework/tasks/parc_dataset.py
def _one_arg(grid):
    out = fn(grid)
    if not _is_int_grid(out):   # [] fails: empty list is not a grid of rows
        raise ValueError(f"P-ARC verifier verify_t{n} returned non-grid output")
    return out

[] is truthy-adjacent but fails _is_int_grid (expects a non-empty list of equal-length integer rows). So a quiet “cannot solve / cannot parse” return becomes a loud tool error for the agent. Most other P-ARC verifiers raise explicit ValueError("expected …") instead — clearer for the model.
